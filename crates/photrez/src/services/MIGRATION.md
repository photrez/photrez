# Native behavior and service census

This inventory records the frozen desktop source, its current native destination or retirement, accountable owner, and the evidence available. The path-keyed owner table below completes the per-source mapping. A destination or existing unit test is not proof of a working native user path. No rows below claim replacement coverage unless a production event reaches the service and verifies its result and failure behavior. Current phase and authorization are tracked in [STATUS](../../../../docs/STATUS.md); the source plan is [70](../../../../docs/plans/2026-10-10-gpui-kit-migration/sub-plans/70-document-logic-native.md).

### A2 clipboard API ruling (2026-10-22)

Correction to the eyedropper cross-cutting row: the pinned GPUI `App::write_to_clipboard(&self, ClipboardItem)` returns `()`, so the native shell cannot observe OS rejection through this API. Per the user's ruling, the service submits the HEX text without a fabricated `Result`, fallback, success toast, or `Copied!` claim. Keep OS rejection visibility as an explicit API limitation; the mounted control/event proof remains owned by `40`/`60`.

Implementation status: `services::clipboard` now exposes the GPUI-backed text writer and helpers over the existing `SettingsStore` key. A headless GPUI test verifies the exact submitted text; file-backed settings tests cover default-off, exact-string parsing, and true/false persistence. UI event wiring and OS rejection visibility remain open in their owning gates.
